# RadFusion PE — independent reproduction + interpretability + leakage audit

Code accompanying the manuscript:

> **A Multimodal Late-Fusion Pipeline for Pulmonary Embolism Detection from CT Pulmonary
> Angiography and Electronic Health Records, with Interpretable EHR Feature Attribution:
> A Reproducibility Study.** Zain A. Jaffar.

This repository reproduces the multimodal late-fusion pulmonary-embolism (PE) detection result on the
public **Stanford AIMI RadFusion** benchmark, re-implements the electronic-health-record (EHR) arm,
combines it with the benchmark's provided imaging scores by late fusion, and audits the EHR arm with
SHAP.

## ⚠️ Read this first — what the imaging arm actually is

The **imaging arm used in every reported fusion result is the RadFusion benchmark's *provided*
study-level vision-model probability** — the `pred` column of `Vision.csv`, generated by the
benchmark's **PENet** imaging model and distributed with the dataset. **This repository does not
retrain an imaging model for the fusion.** Reusing the provided scores keeps the imaging input
identical to the reference benchmark and isolates the reproduction to the EHR arm and the fusion step.

A lightweight **YOLOv8n-cls slice classifier** is included in [`src/exploratory_yolo.py`](src/exploratory_yolo.py)
as a **separate, exploratory** direction. It is evaluated at the slice level only; its scores are **not**
aggregated to study level and **not** used in any reported fusion result. It is a candidate compact
imaging arm for future work, nothing more. Do not interpret the reported 0.80/0.94 numbers as YOLO's.

## Key finding (the point of the paper)

The dominant EHR SHAP feature is a **pulmonary-circulation diagnosis (ICD-10 I26–I28)** whose coding
overlaps the PE label itself. The EHR arm's discrimination — and, because average fusion is a 50/50
blend of the EHR score, the fusion result — may therefore partly reflect **temporal label leakage**
rather than genuine pre-test prediction. See the manuscript Discussion/Limitations and
[`src/interpret.py`](src/interpret.py).

## Data access

The RadFusion dataset is third-party data available from the Stanford Center for Artificial
Intelligence in Medicine and Imaging (AIMI) Shared Datasets programme:
<https://aimi.stanford.edu/datasets> (registration + data-use agreement required). We do not
redistribute the data. The `GDRIVE_FILES` IDs in [`src/config.py`](src/config.py) are the public files
used by the RadFusion Colab tutorial and are provided only for convenience; the canonical source is the
AIMI programme above.

Expected files (placed in `./data/`): `Demographics.csv`, `INP_MED.csv`, `OUT_MED.csv`, `Vitals.csv`,
`ICD.csv`, `LABS.csv`, `Vision.csv`. All are keyed by a study identifier `idx`; `Vision.csv` also
carries `label`, `pred`, `pe_type`, and `split`.

## Reproduce the reported numbers (manuscript revision)

The script that regenerates **every number, table and figure in the revised manuscript** is
[`revision/revision_analyses.py`](revision/revision_analyses.py):

```bash
pip install -r revision/requirements.txt
# place the RadFusion CSVs (Demographics, INP_MED, OUT_MED, Vitals, ICD, LABS, Vision) in ./data/
python revision/revision_analyses.py   # tables -> results/*.csv, results/results.json; figures -> results/figures/
python revision/figure1.py             # Figure 1 (pipeline schematic)
```

It uses the EHR configuration that produced the reported results — the benchmark reference implementation
(per-table zero-variance removal and z-standardization; elastic-net logistic regression with C=0.1,
L1 ratio 0.99, balanced class weights, saga solver, max_iter=1000, seed 0) — and adds bootstrap 95% CIs,
paired DeLong tests, exact linear SHAP, the prespecified label-leakage feature-exclusion ablation, and
sensitivity analyses (training-only standardization; 5-fold cross-validated grid search, which selects the
same hyperparameters). The exact leakage-candidate columns are written to `results/leakage_feature_map.csv`.

The older `run_reproduction.py` below (grid search, extra 1% filter) is kept for reference; it is **not**
the configuration behind the reported numbers.

## Reproduce

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# optional: fetch the tutorial copies of the CSVs into ./data (requires gdown + accepting AIMI terms)
python -m src.data --download

# reproduce Tables 1–3 and the SHAP figures
python run_reproduction.py
```

Outputs (AUROC/AUPRC by modality, operating-point metrics with Wilson 95% CIs and likelihood ratios
for the full cohort and the non-subsegmental subset, and the SHAP plots) are written to `./results/`.

The reported operating points use a fixed 0.5 threshold on each model; the EHR discrimination in
Table 1 is the elastic-net logistic model, whereas the EHR operating point in Table 2 is the
support-vector variant (they are two different estimators by design).

## Repository layout

```
src/config.py            paths, dataset file IDs, column names, constants
src/data.py              download, load EHR tables, build features, join provided vision scores
src/models.py            elastic-net logistic + support-vector EHR estimators
src/fusion.py            average / maximum late fusion
src/metrics.py           AUROC, AUPRC, confusion-matrix metrics, Wilson CIs, likelihood ratios
src/interpret.py         SHAP attribution for the EHR arm
src/exploratory_yolo.py  exploratory slice classifier — NOT part of the reported fusion
run_reproduction.py      end-to-end pipeline that regenerates the reported numbers
```

Reporting follows the TRIPOD+AI statement; a completed checklist accompanies the manuscript (S1 File).

## Limitations (see manuscript for the full list)

Single dataset, single center; no external or prospective validation; test set enriched for PE
(≈58%); AUROC point estimates without confidence intervals or a formal between-arm test; no
calibration or decision-curve analysis; potential temporal label leakage in the EHR arm; imaging arm
is the benchmark's provided scores rather than a model trained here.
